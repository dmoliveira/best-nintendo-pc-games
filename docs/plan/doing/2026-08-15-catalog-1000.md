# Scale GameAtlas to 1,000 games

**Status:** in progress
**Date:** 2026-08-15
**Scope:** catalog data, fact-source policy, genre taxonomy, deterministic generic art, generation, and scale-safe validation

## Goal

Expand GameAtlas from 103 to exactly **1,000** catalog records by adding **897** real Nintendo-family and Windows games. Do not import numeric critic/user/popularity data, provider prose, screenshots, logos, box art, or API assets.

This remains a broad source-aware editorial discovery catalog, not a claim of complete worldwide coverage or a universal ranking.

## Selection and source method

Freeze the 897-entry batch from a Wikidata structured-data Query Service import:

- select only video-game entities with an English label, release date, supported platform, mapped genre, and at least three language sitelinks;
- use sitelinks only as an import-time documentation floor and ordering aid; never store, render, or rank by that number;
- retain QID, title label, deterministically selected Wikidata P577 release year, Wikidata-listed platform/genre IDs, and permanent entity URL in the committed inventory;
- use that entity page only as a labeled outbound factual reference; copy no Wikidata prose, score, image, or popularity field;
- create all descriptions, highlights, rationales, and SVG art independently in GameAtlas;
- reject any candidate that collides with an existing normalized slug, title, or alias.

Register Wikidata in the source-rights policy as a CC0 structured-data source, with the structured-data policy, license/terms URLs, review metadata, and an explicit ban on copied prose/images/numeric ratings. CC0 applies to its structured data, not all Wikidata website content.

## Genre normalization

Keep the current seven genres and add: strategy, fighting, shooter, sports, rhythm, horror, stealth, visual-novel, sandbox, party, survival, educational, and arcade. Reject unmapped source genres rather than forcing them into unrelated categories.

## Generated output

A local importer creates a versioned immutable inventory. A deterministic generator materializes one game JSON, one original abstract SVG, and one matching manifest entry for every candidate. Check-only mode must fail when generated output diverges from the frozen inventory.

Every new game has exactly one nonnumeric GameAtlas original-editorial signal, a direct Wikidata reference link, one generic manifest-backed asset, and no box-front role or third-party media.

## Acceptance criteria

- Exactly 1,000 valid records and exactly 897 unique-QID inventory candidates.
- Every candidate has a direct HTTPS entity URL, valid Wikidata-listed platform, mapped genre, and deterministically selected Wikidata release year.
- No candidate/record stores metrics, sitelink counts, provider prose, images, or score-like fields.
- All 1,000 games have exactly one unique original generic game-card asset and matching manifest provenance.
- Existing governed box-art, secret-scanning, asset-export, and no-art fallback gates remain intact.
- Catalog-1000, rights, catalog, test, build, export, and full validation checks pass.

## Execution batches

1. Register the source and genre taxonomy; add importer/generator/validation scaffolding.
2. Freeze and independently inspect the candidate inventory plus representative QID/platform/genre mappings.
3. Generate four platform-balanced batches, validating rights/catalog/generator output after each.
4. Run source-policy, data/identity/asset, and static-export/performance review passes.

## Risk and review budget

This is a **high-risk, large content and rights slice**. Require three independent review/fix passes. Scale never relaxes no-copy, no-numeric, or asset-provenance requirements.

## Plan-review hardening

### Fact semantics and frozen input

- Release.year means the earliest valid year selected deterministically from Wikidata P577 statements. It is never represented as a platform-qualified release date or a claim of canonical global release data. Platform membership is separately represented as a Wikidata P400 statement in the frozen candidate.
- Commit the exact WDQS query text, platform QID table, genre QID/label mapping, retrieval timestamp, source endpoint, deterministic ordering rule, and SHA-256 snapshot digest with the inventory.
- The importer selects low-volume platform buckets first, deduplicates globally by QID and normalized identity, and records per-platform candidate availability, selected counts, and every transfer to Windows in a quota ledger.
- Candidate selection rejects title suffixes that identify ports, remasters, compilations, or generic editions unless an explicit reviewed exception appears in the reconciliation ledger. P400/P136 remain community-maintained statements and require representative mapping review.
- Commit a normalized-identity snapshot for the existing 103 records. The importer rejects every candidate that collides with this snapshot and records reviewed exception decisions separately.

### Closed candidate schema

The catalog-1000 inventory is closed. Every candidate may contain only: wikidataId, entityUrl, title, aliases, wikidataReleaseYear, platformId, wikidataPlatformId, genreIds, wikidataGenreIds, editorialCopy, and review. No unknown keys are allowed.

The only permitted review fields are reviewedBy, reviewedAt, copyStatus, and sourceMethod. The source method must be fact-only-wikidata. The importer must reject source prose, images, metrics, sitelink counts, scores, ranks, value fields, and any unknown nested key.

### Enforceable Wikidata policy

- Add a dedicated approved wikidata-fact-reference source record with the Wikidata structured-data policy URL, CC0 legal-code URL, Wikimedia terms URL, data-access URL, query-service URL, attribution text, allowed structured-field whitelist, review/recheck dates, and a covered process limited to a title label, P577 year, P400/P136 statements, QID, and an outbound entity URL.
- Extend rights validation to require that complete contract for this source and reject any generated record that uses it outside the fact-only fields.
- Require every candidate QID to match Q followed by digits, every entity URL to equal https://www.wikidata.org/wiki/<QID>, every generated link to match that same QID, and every generated sources array to include wikidata-fact-reference and gameatlas-editorial.

### Exact output closure

- Add validate:catalog-1000. It validates the closed inventory, exactly 897 unique QIDs, exactly 1,000 game files, exact selected/transfer quota totals, and one generated game, SVG, and manifest entry per inventory candidate.
- The validator rejects stale generated records, assets, manifest entries, and QID references not present in the inventory. It requires exactly one original-editorial signal and one generic non-box asset per generated game.
- Each generated SVG manifest entry includes a SHA-256 content checksum. The validator recomputes it, verifies unique bytes/path/provenance, and rejects any generated SVG containing text, image, title, logo, or external-reference elements.
- Add candidate-wide exact duplicate and normalized n-gram similarity checks for descriptions, highlights, and rationales after removing title tokens. Each candidate must carry a named frozen-catalog-method attestation that distinguishes the reproducible workflow from a title-by-title human review.

### Measurable scale exits

- Static export must contain exactly 1,000 game routes and 1,000 game sitemap entries.
- A clean build must finish within 180 seconds and the complete `out` artifact must stay below 150 MiB. The budget accounts for Next App Router's required static HTML plus Flight/prefetch payloads for 1,000 client-navigable routes; it is still measured on every export validation.
- The homepage must render exactly 24 initial cards and keep its combined HTML/Flight payload below 512 KiB; the fetched compact search index must stay below 2 MiB.
- The public search index must be a schema-versioned envelope whose client-side SHA-256 projection digest matches the digest embedded in the server-rendered page; malformed or stale payloads fail closed to the bounded initial page.
- The final report records measured elapsed build time, artifact bytes, static route count, and the number of source links sampled from the frozen QID set.
